| `backend/.env` | `MONGODB_URI` → `...?replicaSet=rs0` (was `directConnection=true`) | License writes run inside MongoDB transactions (`src/utils/transaction.js`); `directConnection=true` cannot start multi-document transactions. A single-node replica set is mandatory. |

A clean data directory was used instead. Note this means **any pre-existing production-like data in that directory is not loaded** — it would require a MongoDB 8.2 server.

## 5. Bugs found (6, all unfixed)

### BUG 1 — Invalid or expired JWT returns HTTP 500 instead of 401 · **High (security)**

`src/utils/Token.js:14` returns `null` when `jwt.verify` throws, so the `catch` block in `src/middleware/auth.middleware.js:26` is **dead code** and line 31 executes `req.user = null`. `req.user` is then dereferenced by controllers.

| Route type | Result |
|---|---|
| `protect` + `restrictTo(...)` | `401` — safe by accident, `restrictTo` null-checks |
| **`protect` only** | **`500` — `Cannot read properties of null (reading 'userid')`** |

Verified directly against the running API for both a garbage token and a correctly-signed but expired token:
```
GET /api/user/me  (Bearer not.a.jwt)                    -> 500
GET /api/user/me  (expired, valid signature)            -> 500
GET /api/product  (Bearer not.a.jwt)                    -> 401  (by accident)
```

Affected: every route with `protect` and no `restrictTo` — including `/api/user/me`, `/api/user/update/me`, `/api/user/below-role-users`, `/api/dashboard/*`, `/api/analytics/user`, `/api/license/own-licenses`, `/api/renewal/*`. These are user-facing, so an expired session produces a server error rather than a re-login prompt.

**Fix:** make `verifyAccessToken` rethrow, or null-check in `protect`:
```js
decoded = verifyAccessToken(token);
if (!decoded) return next(new ApiError(401, "Invalid or expired token"));
```

### BUG 2 — `GET /api/license/hierarchy/:id` fails 100% of the time · **High**

`src/controllers/license.controller.js:1139` reads `license.licenseType.name`, but the schema field is **`licenseTypeId`** (`src/models/license.model.js:6`) and is an unpopulated ObjectId. Result: `TypeError` → `500` on every call, for every license, for every role.

```
GET /api/license/hierarchy/6abd0223bb60c9c03d1cccb1
-> 500 {"success":false,"message":"Cannot read properties of undefined (reading 'name')"}
```

Secondary defect on the adjacent line 1135: `console.log(ownerUser.role)` will throw if the owning user has been deleted — an unguarded dereference in a request path (and a stray `console.log` in production code).

**Fix:** `licenseType: license.licenseTypeId?.name` after populating, or `.populate("licenseTypeId", "name")`; guard `ownerUser`.

### BUG 3 — `GET /api/smart-reminder/my-peak-time` fails 100% of the time · **High**

`src/controllers/Smartreminder.controller.js:41` uses `req.user._id`, but the JWT payload key is **`userid`** (`src/services/user.service.js:41` — `generateToken({ userid: user._id, role })`). Two independent defects:

1. Wrong property name — would be `undefined` even with a valid token.
2. The route is **missing `protect` entirely** in `src/routes/Smartreminder.route.js`, so `req.user` is never populated. Its own docblock says `@access Private`.

Verified: `500` with a valid customer token **and** `500` with no token. The sibling `GET /peak-time/:userId` works correctly (`200`).

**Fix:** add `protect` to the route and change to `req.user.userid`.

### BUG 4 — `GET /api/feature-registry/:productId` returns 500 on a malformed ID · **Medium**

No param validation. A non-ObjectId reaches `FeatureRegistry.findOne({ productId })` where the field is an ObjectId ref:
```
GET /api/feature-registry/not-an-object-id
-> 500 {"success":false,"message":"Cast to ObjectId failed for value \"not-an-object-id\""}
```
A well-formed but unknown ID correctly returns `404`, so this is purely a missing-validation gap. Same class of bug as BUG 5.

### BUG 5 — `GET /api/license/buy/:id` returns 500 on a malformed ID · **Medium**

`src/routes/license.route.js` registers `/buy/:id` with no `validateParams(licenseIdParamSchema)`, unlike its siblings (`/licenses-by-product/:id`, `/delete/:id`, `/update/:id`, `/:id`) which all validate. Leaks a raw MongoDB driver error to the client.

### BUG 6 — Frontend lint: 65 errors, 17 warnings · **Medium**

`npm run lint` in `frontend/`:

| Rule | Count |
|---|---|
| `no-unused-vars` | 46 |
| `react-hooks/exhaustive-deps` | 17 |
| `react-hooks/static-components` | 4 |
